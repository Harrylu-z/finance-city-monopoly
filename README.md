## 快速开始

### 环境要求

- **Python 3.8+**（用于本地静态服务器，零第三方依赖）
- 现代浏览器（Chrome / Edge / Firefox / Safari，需支持 ES Modules）

> 项目**不需要 Node.js**，也不需要任何构建步骤、npm 包或打包器。

### 运行

```bash
# 方式一：一键启动（自动打开浏览器）
python serve.py

# 方式二：指定端口
python serve.py 8080

# 方式三：不自动打开浏览器
python serve.py 8080 --no-browser
```

启动后访问终端提示的地址（默认 <http://127.0.0.1:8000/>）。

> **为什么不用 `python -m http.server`？**
> `serve.py` 额外做了三件事：
> 1. **双栈监听（IPv4 + IPv6）** —— 浏览器访问 `localhost` 时会先尝试 IPv6，
>    如果服务端只监听 IPv4，浏览器要等约 2 秒 TCP 超时才会回退，首屏极慢；
> 2. **显式 MIME 类型** —— 保证 `.js` 以 `text/javascript` 返回，ES Module 才能正常加载；
> 3. **多线程处理** —— 23 个模块并发加载时不会互相阻塞。

### 校验项目完整性

```bash
python tools/check-imports.py
```

会扫描 `src/` 下所有相对 `import` 路径，确认没有 404。

## 玩法说明

### 基本循环

**掷骰 → 移动 → 结算 → 回合结束**

### 你的回合可以做什么

| 操作 | 按钮 | 说明 |
|---|---|---|
| 掷骰 | `掷 骰 子` | 1~3 颗骰子，点数累加；空格 / 回车也可触发 |
| 收购 | 落点弹窗 | 无主机构可用「战略入股」方式收购（文案内化为收购 30% 股权） |
| 升级 | `我的机构` | 把网点升级为支行 → 分行 → 总部 → 地标（**须再次踏足自有地块**） |
| 质押融资 | `质押融资` | 把机构抵押换取现金（文案内化为股权质押融资 / 资产证券化） |
| 赎回 | `我的机构` | 支付解押费赎回已质押机构 |
| 央行贷款 | 起点弹窗 | **经过起点**（路过即得，不必恰好停留）后可选档位贷款（与质押融资相互独立） |
| 发行债券 | 再融资窗口弹窗 | 向其他玩家募资，需 **≥2 人认购**方能成立 |
| 交租 | 落点弹窗 | 踩到他人机构时**弹出交租确认窗**，展示机构立绘、归属人、等级与租金构成 |
| 结束回合 | `结束回合` | 交棒给下一位玩家 |

### 弹窗提醒

关键结算不再只播报一行字，而是**主动弹窗**：

| 弹窗 | 触发条件 | 内容 |
|---|---|---|
| 交租确认 | 踩到他人持有的机构 | 机构立绘 + 归属人 + 等级 + 租金构成（基础租金 × 集团系数 × 行情系数 × Buff）+ 交租后余额 |
| 央行贷款 | **经过起点**（路过或停留） | 三档额度与利率，含「暂不借款」按钮 |
| 收购确认 | 落在无主机构 | 买入价、等级、地标附加费 |
| 事件卡 / 陷阱卡 | 抽到事件卡或触发陷阱 | 卡面与结算明细 |
| 债券发行 | 停在再融资窗口 | 面向其他玩家的认购征集 |

AI 玩家的交租**不弹窗**（仅写播报），避免打断观战节奏。

### 资产排行下钻 · 财务指标

右侧「资产排行」面板的**任意一行都可点击**（含 AI 玩家），打开「财务指标 · 下钻」窗口，
查看该玩家的完整财务画像。也可从菜单 → `财务指标总览` 打开自己的指标。

窗口分四个板块：

| 板块 | 指标 |
|---|---|
| 资产结构 | 总资产、现金、机构市值、质押资产 |
| 负债与净值 | 总负债、未偿贷款、应付债券、质押融资额、持有债券债权、净资产、资产负债率 / 权益比率 / 权益乘数（带比例条） |
| 经营指标 | 在营机构、质押机构、监管牌照、机构平均等级、最高等级、每圈管理费收入、圈均摊薄收入 |
| 现金流与交易统计 | 累计收取 / 支付管理费、管理费净流入、收购次数、升级次数、单笔最高管理费 |

**指标口径**

- **总资产** = 现金 + 机构市值；**已质押的机构按半值计入**（与排行榜排名口径一致）
- **总负债** = 未偿贷款（含利息）+ 应付债券兑付义务 + 质押融资本金
- **净资产** = 总资产 − 总负债；**资产负债率 + 权益比率 = 100%**
- **每圈管理费收入** 按当前市场周期（集团 Buff、事件卡系数一并计入）折算
- 破产玩家同样可下钻，指标显示其清算后的状态

> 指标由纯函数 `financialMetrics(player, state)` 计算（`src/core/economy.js`），无副作用、可单测。

### 金融主题文案对照

| 大富翁原概念 | 本作包装 |
|---|---|
| 买地 | 收购经营权 / 战略入股（30% 股权） |
| 租金 | 管理费 / 牌照手续费收入 |
| 升级建筑 | 升级总部大楼 / 增设网点 / 扩表 |
| 抵押 | 股权质押融资 / 资产证券化 |
| 破产 | 爆仓清算 / 强制平仓 / 摘牌退市 |
| 掷骰子 | 行情骰 / 交易机会 |
| 起点奖金 | 货币发行 / 流动性投放补贴（+￥300） |

### 破产与清算

现金一旦为负即触发**追缴保证金（Margin Call）**，不允许带着负现金继续游戏：

- 回合结束时现金为负 → 必须先**追加质押**补足缺口（按质押可得金额从高到低质押），
  补足后才能结束回合；玩家会看到强制补足窗口，可逐家质押或一键补足。
- 若全部机构已质押仍补不足 → **强制平仓**：机构股权按规则折价清算，角色离场，
  回合轮转会**自动跳过**破产玩家。破产结算面板会展示清算明细。
- 央行贷款到期现金不足，同样先追保、补不足才平仓（见「央行贷款」）。
- AI 玩家由系统自动完成追保，不会卡在负现金状态。

### 游戏结束

只剩 1 名未破产玩家时结束，弹出胜利结算画面（含撒花特效 + 资产排行榜 + 分享入口）。

| 键 | 作用 |
|---|---|
| `空格` / `Enter` | 掷骰 |
| `Esc` | 关闭当前弹窗 |

## 棋盘设计

**67 格 = 47 个普通机构格 + 4 个监管机构格 + 16 个特殊格**（含 2 块赌场格）。

### 棋盘形状 —— 正方形环道（连续闭合 · 经典大富翁）

布局为 **一条连续的闭合环道**：67 个格子沿正方形（四边等长）均匀分布，
四个角位于 index 0 / 17 / 34 / 51 —— 经典大富翁的直角方形赛道。

```
                  index 17 ─┐
        index 0 ────────────┐│
      (起点·右侧中点)        ││
                           ↓↓  ← 顺时针推进
        index 66 ──────────┘│
                           └─ index 67 ≡ index 0（闭环）
```

设计要点：

| 特性 | 说明 |
|---|---|
| **连续闭环** | 67 个格子中心沿**同一条闭合曲线**等弧长分布；index i 与 i+1（含 66→0）的间距误差 < **0.5%**，棋子绕圈全程连贯，**绝无瞬移** |
| **正方形赛道** | 四边等长 —— 上 / 右 / 左各 18 格、底边 17 格（角格由相邻两边共享），合计 18+18+18+17−4 = **67** 格 |
| **可读性强** | 直角方形是经典大富翁棋盘的形态，玩家无需额外适应；文字严格水平，不随轨道旋转 |

> **为什么不用「外环 + 内环」双环？**
> 早期版本把 63 格拆成外环 40 格 + 内环 22 格 + 中心 1 格。
> 看上去是两个独立的圈，但 index 39（外环末）与 index 40（内环首）在几何上
> **并不相邻** —— 棋子从外圈拐进内圈时会「瞬移」，地图看起来是断开的。
> 现在改为**单条闭合环道**，从根上消除了这个问题。

形状数据集中在 `src/core/board-shape.js`：

- `TRACK_POINTS` —— 67 个采样点（归一化到 0..1000），即各格中心的轨道坐标；
- `trackGap(i)` —— 相邻两格的**显示尺度**距离（x 按 2a、y 按 2b 还原）；
- `trackSpacing()` —— 全环平均间距。

渲染层（`render/canvas.js`）只做「轨道坐标 → 屏幕矩形」换算，不重复推导拓扑。
自检用例强制校验：**最大间距 ≤ 平均 × 1.2**（杜绝瞬移）、
**最小间距 ≥ 平均 × 0.8**（杜绝重叠）、**闭合边 66→0 同样达标**。

### 槽位表 —— 声明式布局

棋盘不是「按顺序 push」拼出来的，而是用一张**显式槽位表** `LAYOUT` 逐格声明
（`'b0'`~`'b10'` 银行、`'r0'`~`'r10'` 券商、`'i0'`~`'i10'` 保险、`'a0'`~`'a11'` 资管，
`'P'`/`'C'`/`'N'`/`'F'` 四家监管机构，其余为特殊格 id）。

这样做的原因是：**功能格（特殊格 + 监管格）必须均匀穿插在普通机构格之间**。
旧写法很容易把功能格挤到相邻位置，槽位表则让分布一目了然，且可以在构建期强制校验：

- `assertNoAdjacentFunctionalCells()` —— 导入 `board.js` 时校验任意两个功能格不相邻，
  一旦有人排到一起就**导入即报错**，不会静默劣化；
- `validateBoard()` —— 校验清算所目标是普通机构格、目标不重复、跨 ≥3 个区段分散。

### 界面布局

桌面端为**三栏网格**（CSS Grid）：

```
┌──────────────────────────────────────────────┐
│  顶部：当前回合 / 行情 / 功能按钮              │
├────────┬────────────────────────┬────────────┤
│ 玩家卡片│     正方形环道棋盘        │ 资产排行   │
│  (左栏) │      (中栏，独立行)      │ 行情灯带   │
│        │                        │  (右栏)    │
├────────┴────────────────────────┴────────────┤
│  底部：回合播报（可加长） + 动作按钮           │
└──────────────────────────────────────────────┘
```

**回合播报栏**高度为 `clamp(150px, 26vh, 300px)`（原固定 108px）。
它位于 stage 网格的 `bottom` 行 —— 加高时会**自动压缩棋盘所在的行**，
因此播报栏变长**不会覆盖地图**；`max-height: 300px` 兜底，极端矮窗口也不会顶穿布局。

### 集团内部的价格/租金梯度

每格机构有 5 个等级，**价格与租金严格递增**（自检会逐格校验）：

| 等级 | 名称 | 体积表现 |
|---|---|---|
| 0 | 网点级 | 最矮，细节最少 |
| 1 | 支行级 | 略高，多一层 |
| 2 | 分行级 | 中等高度，窗格更多 |
| 3 | 总部级 | 高层，完整幕墙 |
| 4 | 地标级 | 最高 + 顶部标志物 / 皇冠 |

集团内前 3 格低价小型机构 → 中段区域总部 → 后段全国性总部 → 末格行业标杆。

### 四大监管机构（可持有 · 不可升级）

监管格是**买断式经营权格**：占用大量现金，但**不能升级**（`maxLevel` 固定为 0），
持有后对**全局**生效，不只是给自己加成 —— 这是本作最硬核的一层设计。

| 索引 | 机构 | 买入价 | 全局效果 |
|---|---|---|---|
| 15 | 中国人民银行 | ￥3200 | **流动性投放**：持有者每圈开始额外获得 +￥80 |
| 30 | 中国证监会 | ￥3400 | **注册制便利**：全体玩家升级费用 −12% |
| 45 | 金融监管总局 | ￥3000 | **审慎约束**：全体玩家租金收入 −8% |
| 57 | 金融稳定委员会 | ￥3600 | **风险缓冲**：持有者触发陷阱格时罚金减免 50% |

> 监管机构采用**紫金配色 + 双描边**，与普通机构的单色边框一眼可辨；
> 建筑立绘使用专属徽记（梅花币章 / 盾形刻章 / 齿状圆章 / 天平）。

### 特殊格（16 个）

特殊格**均匀穿插在普通机构格之间**，任意两个功能格（特殊格 + 监管格）都不相邻，
相邻功能格间隔 2~6 格 —— 落点分布更均匀，不会出现「连片特殊格」。

## 职业系统（7 种金融角色）

开局界面可选择职业，**职业与棋子立绘一一对应** —— 从棋子上就能认出对手是谁。
玩家**不能自由选择棋子外观**：立绘完全由职业决定（真人玩家同样如此）。
每个职业自带一个**温和**的被动：只做效率修正或小额缓冲，
既不会「免租 / 免罚 / 免债」，也不会直接改写胜负。

| 职业 | 出场被动 | 效果 | 专属棋子立绘 |
|---|---|---|---|
| **投行家** | 承销定价 | 收购机构价格 **−8%** | 分分头 + 领带 + 承销文件 |
| **风控总监** | 风险缓冲 | 监管陷阱罚金 **−30%** | 寸头 + 徽章 + 检查清单 |
| **精算师** | 精算费率 | 自己收取的管理费 **+6%** | 眼镜 + 计算器 |
| **量化研究员** | 模型优势 | 德州扑克中坏牌判定更保守（更少弃牌） | 发光终端 + 目镜 |
| **基金经理** | 长期持仓 | 机构升级费用 **−6%** | 银侧分头 + 保温杯 + 围巾 |
| **交易员** | 择时交易 | 每圈首次踩到牛熊切换格额外 **+￥120** 价差收益 | 反戴鸭舌帽 + 耳麦 + 行情屏 |
| **赌王** | 庄家之眼 | 德州扑克起始手牌比其他玩家 **多 1 张**（3 张底牌） | 礼帽 + 领结 + 扑克牌 |

> **平衡性约束**（由 `validateCareers()` 在自检中强制校验）：
> 乘数类被动偏离 1 不超过 **15%**，固定加成不超过 **￥300**。
> 7 种职业的被动钩子互不重复，7 张棋子立绘两两不同。

**职业与存档**：职业 id 随设置项写入本地存储，也编码进分享深链接（`?career=king`）；
旧存档没有该字段时自动降级为「投行家」，不会崩溃。

**立绘与存档**：棋子立绘**不序列化** —— 它由职业在建局时直接解析。
旧存档 / 旧分享链接里遗留的 `avatar` 字段会被**安全忽略**，不影响任何显示。

## 私人赌场 · 德州扑克

棋盘上有 **2 块赌场格**（index 25 / 64）。任意玩家踩入，**全体玩家同桌**开一局德州扑克。

### 规则

| 项目 | 设定 |
|---|---|
| 牌库 | **严格一副 52 张**，每局独立洗牌 |
| 底牌 | 每人 2 张；**「赌王」3 张** |
| 盲注 | 小盲 / 大盲按当前回合自动递增 |
| 公共牌 | 翻牌 / 转牌 / 河牌各 1 张，共 **5 张**（每街烧 1 张） |
| 牌型 | 皇家同花顺 → 同花顺 → 四条 → 葫芦 → 同花 → 顺子 → 三条 → 两对 → 一对 → 高牌 |
| 下注 | 弃牌 / 过牌 / 跟注 / 加注（3 档）/ 全下 / 随时退出 |
| 结算 | 底池 + 边池分别派彩，同牌型按筹码位置分配 |

### 资产下注（不破坏主游戏）

玩家可下注**现金 + 资产折让额度**：

- 资产额度 = 资产总市值 × **50%**，仅作为**本局的额外下注额度**；
- 使用资产额度下注时，会在玩家身上记录一个临时「资产折让」标记，
  使 `totalAssets()` 的估值相应下调 —— **不改变机构所有权、等级、质押状态**；
- **现金永不为负**：扣款顺序为「先扣现金 → 现金不足再动资产额度」，
  两者都耗尽则无法继续加注；结算时还有一道兜底 `if (p.cash < 0) p.cash = 0`；
- 单局加注受 `maxBetRatio`（35%）约束 —— **一把牌不会毁掉主游戏**。

### 「赌王」的额外底牌与 52 张硬约束

- 额外底牌**只影响发牌轮次**，不复制牌库；
- 发牌策略为**逐张轮转发牌**（每人 1 张，循环至发满），
  因此 4 人局（含赌王）底牌最多 9 张；
- 加上 5 张公共牌 + 3 张烧牌，**全局最多动用 17 张 < 52**；
- 每一步发牌后都执行 `assertDeckIntegrity()`：校验
  `已用牌 + 烧牌 ≤ 52` 且**无重复牌**。

### 结束与退出

- **打完摊牌** → 结算并展示结果表 → 点「返回主游戏」恢复回合；
- **中途退出** → `abortPokerGame()` 把剩余玩家标记为弃牌、按规则分配底池，
  同样正常结算回主游戏；
- 两种路径都会清空 `state.poker` / `state.pending`，并把控制权交回原玩家的回合。

## 融资工具

三种融资手段并行，各有代价，互不排斥：

### 1. 股权质押融资（随时可用）

把自有机构抵押换取现金（市值 × 0.55），赎回需付 12% 解押费。
代价是**租金收入停止**，且机构在被赎回前无法升级。

### 2. 央行贷款（经过起点后）

**只要经过起点格就能拿到补贴并获得贷款机会** —— 不要求「恰好停在起点」。
移动路径跨过起点（绕圈）或落在起点，都会发放 ￥300 货币发行补贴，
并弹出贷款选择，**利率与金额均可选**，共三档：

| 档位 | 额度 | 单利 | 期限 | 每回合利息 | 到期还本 | 定位 |
|---|---|---|---|---|---|---|
| 支小再贷款 | ￥1200 | 3% / 回合 | 4 回合 | ￥36 | ￥1200 | 小额流动性支持，期限最短 |
| 过桥资金 | ￥2400 | 3% / 回合 | 6 回合 | ￥72 | ￥2400 | 额度与期限均衡 |
| PSL 棚改 | ￥4000 | 3% / 回合 | 8 回合 | ￥120 | ￥4000 | 政策性工具，额度大、期限长 |

- 每圈**最多申请一次**（按你自己的圈计）
- **期限按你自己的回合数计**：借入当回合不扣息，之后每个自己的回合扣当期利息，
  第 N 个自己的回合归还本金 —— 不会被别的玩家绕圈催收，也不会「刚借一轮就要求还钱」
- **还息与还本分离**：利息按回合从现金中扣除；现金不足时当期利息转为「欠息」，
  到期连同本金一并结清（欠息会在融资面板中单列）
- 本金到期未足额归还则触发**强制破产清算**
- 额度、期限、利息互相匹配：借得越多期限越长，单利统一 3%/回合，
  总利息 = 3% × 期限（12% / 18% / 24%）
- 设计意图：地标级机构动辄 ￥6000+，靠现金滚存几乎不可能，
  必须用杠杆去够 —— 但杠杆有明确的到期日与成本

### 3. 债券发行（再融资窗口格）

落到「再融资窗口」后，可向**其他玩家**发行债券：

- 每人认购面值 ￥800，**票息由发行人财务状况决定**（并非固定值）：
  基础 6%，资产负债率超过 40% 后每 10 个百分点 +1.5%，净资产为负再 +2%，
  净资产雄厚则 −1%，最终限定 5% ~ 18%
- 期限 **3 圈**，每圈结束时向认购人支付一次票息，到期兑付本金
- **发行成败由市场随机决定**：其他玩家按「票息吸引力 + 自身现金 + 市场风险偏好 + 随机噪声」
  独立认购，发行人**无法自行指定**谁认购；≥2 人认购才成功
- 票息越高越容易募到钱，但高票息本身也暴露了发行人较差的财务状况

> 发行方每圈需支付 `票息 × 认购人数`；若中途现金不足同样会破产。
> 这让「借钱扩张」与「按时还本付息」形成真实的财务压力。

## AI 性格系统

AI 玩家同时拥有 **职业** 与 **性格** 两层属性，二者**正交**、互不约束：

| 层级 | 作用位置 | 内容 | 来源 |
|---|---|---|---|
| **职业** | 规则层（被动） | 收购价 / 升级费 / 租金 / 罚金 / 择时收益 等结构性乘数 | `src/core/careers.js` |
| **性格** | 决策层（偏好） | 出手阈值 / 升级门槛 / 风险容忍 / 集团偏好 等软偏好 | `src/core/personalities.js` |

性格**只改变「怎么做、敢不敢赌」**，绝不直接改写现金流、租金与胜负 ——
因此没有哪种性格能必然获胜，也不存在「某性格直接决定走势」的情况。

5 种性格（每局按 seed 随机分配，尽量不重复）：

| 性格 | 现金留存 | 贪婪度 | 升级偏好 | 风险容忍 | 偏好集团 | 短板 |
|---|---|---|---|---|---|---|
| 激进型 | 10% | 1.22 | 0.62 | 0.72 | 券商 / 资管 | 现金留存低，遇突发支出易被动 |
| 保守型 | 44% | 0.80 | 0.32 | 0.24 | 银行 | 出手慢，容易错过低价窗口 |
| 囤积型 | 30% | 1.06 | 0.20 | 0.42 | 全部（垄断同集团） | 只占不升，单点管理费收益偏低 |
| 现金流型 | 34% | 0.90 | 0.92 | 0.38 | 保险 | 不铺牌照，资产广度差 |
| 杠杆型 | 8% | 1.10 | 0.68 | 0.86 | 券商 / 资管 / 银行 | 杠杆最高，爆仓风险最明显 |

所有参数都以 **中性基准**（`cashReserve 0.28 / greed 1.00 / upgradeBias 0.50 /
riskTolerance 0.45 / rentFocus 0.75 / chaseLowTier 0.50 / concentration 0.40`）
为中心做温和偏移（`greed` 偏离 ≤ 25%），确保各性格胜率差异落在随机波动范围内。

### 性格如何影响决策

1. **收购阈值** —— 出手前必须留出 `cashReserve × 现金`；现金越紧，保守型越容易放弃。
2. **升级门槛** —— 以「每投入 1 元换来的租金增量」衡量性价比，门槛随 `upgradeBias` 放宽或收紧。
3. **杠杆意愿** —— `riskTolerance` 决定 AI 是否愿意质押融资、借贷、认购债券。
4. **集团偏好与集中度** —— `preferGroups` / `concentration` 决定买哪个集团、是否垄断同一条线。
5. **决策播报** —— 每次买/卖都会在回合日志里留下带性格的短台词。

### 真人玩家

真人玩家**不会被分配性格**：`personalityId` 恒为 `null`。
性格只属于 AI —— 人类玩家自行决策，不受性格阈值影响。

### 存档 / 分享兼容

| 场景 | 行为 |
|---|---|
| 新开局 | AI 按 seed 稳定分配职业 + 性格（分享链接可完整复现） |
| 旧存档（AI 缺 `personalityId`） | 降级为 `neutral`（中性基准），行为不变、不追溯改写历史 |
| 旧存档（`personality` 为旧版定义对象） | 正确解析出 `personalityId` |
| 非法 `personalityId` / `careerId` | 静默降级，不抛错、不阻断开局 |
| 真人携带 `personalityId` | 一律忽略，强制为 `null` |

### 随机性设计

1. **决策扰动** —— 每次决策在「性格基线 × 难度贪婪 × (1 ± 噪声)」上取值，
   噪声范围由难度决定（新手 0.50 / 普通 0.32 / 老手 0.18）。
2. **抽风** —— 小概率触发「梭哈」「追高被套」「突然清仓」。
3. **加仓重掷** —— 掷骰前基于资产排名与性格判断是否使用「打新/加仓」道具重掷一次。
4. **决策播报** —— 每次买/卖都会在回合日志里留下带性格的短台词。

### 难度

| 难度 | 决策准确率 | 噪声 | 贪婪 | 风险 |
|---|---|---|---|---|
| 新手 | 0.55 | 0.50 | 0.75 | 0.35 |
| 普通 | 0.75 | 0.32 | 1.00 | 0.50 |
| 老手 | 0.92 | 0.18 | 1.15 | 0.68 |

### 不作弊保证

`decide(state, player, decision, ctx)` 的签名**不接受骰子结果**。
自检里有一条专门断言：调用 `decide` 后返回对象中不含 `dice` / `total` 字段。

### 关键设计

**零外部资源。** 所有建筑、角色、图标、背景都是运行时用 Canvas 程序化绘制的，
仓库里没有任何 `.png` / `.svg` / `.mp3` 文件。调色板统一取自 `src/core/palette.js`
的 32 色。

**确定性随机。** 所有游戏内随机都走 `makeRng(seed)`（Mulberry32），
不使用 `Math.random()`，因此同一个 seed 必然复现同一局。

**纯函数经济层。** `economy.js` 里的 `calculateRent` / `upgradeCost` /
`mortgageValue` / `redeemFee` / `totalAssets` 全部无副作用，可直接单测。

**财务指标单一数据源。** 资产排行下钻窗口的所有指标都来自
`economy.js` 的 `financialMetrics(player, state)` —— 一个纯函数，
既供 UI 展示，也被自检逐项校验（口径、负债拆分、质押处理、周期敏感性）。
UI 不做任何二次计算，避免"排名看到的"和"下钻看到的"对不上。

**棋盘与 HUD 分栏解耦。** 界面用 CSS Grid 划出「顶部条 / 左栏玩家信息 / 中栏棋盘 /
右栏排行+行情灯带 / 底部播报」五个命名区域，**棋盘独占中栏**，
左右面板不再浮在棋盘之上遮挡地图。棋盘画布按 `#board-wrap` 的实测尺寸绘制，
用 `ResizeObserver` 跟随容器变化，并以「尺寸未变则跳过」保证幂等
（重设 `canvas.width` 会清空画布并触发观察者回环）。
格子按 9:7 的自然比例**居中留边（letterbox）**，不会被容器拉伸变形；
背景层 `#stage-bg` 仍铺满整个 stage，天际线视差保持全屏效果。

**非节流调度器。** 浏览器会把后台标签页的 `setTimeout` 节流到最低 1 次/秒，
并暂停 `requestAnimationFrame`，导致回合流程在切走标签页后卡死。
`src/core/scheduler.js` 用 `MessageChannel` 绕开计时器队列，
保证游戏逻辑在后台也稳定推进（画面则由 RAF 负责，后台不刷新）。

**时间驱动的逐格动画。** `MoveAnimator` 基于 `performance.now()` 而非帧计数，
因此动画时长与帧率无关；同时带兜底截止时间，即使渲染循环被完全暂停也能收尾。
`MoveAnimator.frameState(rectOf, slotOf)` 会同时插值「目标格矩形」与「格内棋子槽位偏移」，
跳跃中的棋子与落位后的静态棋子使用同一套坐标计算，落位时零跳变、无视觉错位。

**升级许可作为状态而非 UI。** 「需再次踏足才能升级」不是弹窗层的判断，
而是写在 `state` 里的 `player.upgradePermits[cellIndex]` 标记：
踩到自有地块时由 `settleOnCell` 发放，`upgradeInstitution` 校验并消费。
这样 AI 与玩家走的是同一条路径，规则无法被绕过。

### 经济参数 — `src/core/economy.js` 的 `CONFIG`

| 参数 | 默认值 | 含义 |
|---|---|---|

| `mortgageRatio` | `0.55` | 质押融资比例（按当前市值） |
| `redeemFee` | `0.12` | 解押手续费比例 |

| `marketCycleRounds` | `3` | 每多少圈切换一次牛熊 |

### 机构定价 — `src/core/board.js`

每个集团通过 `GROUPS[group].entries` 定义 11~12 家机构的 `price[]` 与 `rent[]` 数组
（长度 5，对应 5 个等级）。改这里即可整体调整某个集团的定价曲线。

监管机构在 `REGULATORS` 中单独定义（`price` / `maxLevel: 0` / `effect`），
不参与集团定价曲线的递增校验。

### 等级倍率 — `src/core/board.js` 的 `LEVELS`

### AI 性格 — `src/core/ai.js` 的 `PERSONALITIES`

每个性格对象包含 `cashReserve` / `greed` / `upgradeBias` / `riskTolerance` /
`preferGroups` / `rentFocus` / `quote`。

### 调色板 — `src/core/palette.js`

32 色金融都市配色，全项目统一引用。修改这里即可整体换肤。

## 像素风实现要点

| 要求 | 实现 |
|---|---|
| 统一像素网格 | 所有精灵原生 16×16 / 32×32 / 16×24，渲染时整数倍放大 |
| 禁止非整数缩放 | `imageSmoothingEnabled = false` + CSS `image-rendering: pixelated` |
| 硬边缘无羽化 | 全部用 `fillRect` 绘制，不使用 `arc()` / `filter` / `blur` |
| 1px 描边 | `pixeldraw.js` 的 `outline()` 统一处理 |
| 三层体积感 | 色阶 + 高光 + 阴影三档，不用渐变 |
| 受限调色板 | `palette.js` 定义 32 色，所有绘制只能取用 |
| 离散帧动画 | 角色 4 帧行走、骰子翻滚帧、逐格跳跃 squash/stretch |
| 帧化 CSS 动画 | 所有 keyframes 以 `steps()` 离散变化 |
| 粒子用离屏精灵 | `effects.js` 用小 Canvas 批量绘制，不做 CSS 滤镜 |
| 昼夜四档 | 晨 / 午 / 黄昏 / 夜，切换天空色板 + 霓虹强度 |
| 背景视差 | 3 层天际线 + 像素云 + 出租车 + K 线灯带 + 交易所钟楼 |
| 音效 | WebAudio 合成方波/三角波 8-bit 音效，零音频文件 |

### 机构立绘的差异化

每家机构的建筑不是「同一栋楼换个颜色」，而是由 `cell.index` 派生的种子驱动，
组合出六条独立的变体轴：

| 变体轴 | 取值 | 表现 |
|---|---|---|
| `winCols` | 2 / 3 / 4 | 立面窗列数 |
| `bandStep` | 3 / 4 | 横向分隔带间距 |
| `roof` | flat / step / setback / spire | 屋顶造型（平顶 / 台阶 / 退台 / 尖顶） |
| `annex` | none / awning / wing / mast / vents | 附属构件（雨棚 / 侧翼 / 旗杆 / 机组） |
| `sign` | band / plate / box | 招牌样式 |
| `facade` | none / groove / belt / grid | 立面纹理（凹槽 / 腰线 / 网格） |

此外每栋建筑立面上会烙一枚 **3×3 像素指纹徽记**（9 位由种子决定的明暗格），
保证 47 家机构的精灵图两两不同 —— 自检项「机构立绘互不相同」会逐像素比对校验。

五大等级的高度阶梯为 `16 → 20 → 25 → 30 → 36` 像素，
地标级另起 `32×48` 的摩天体量，与普通机构一眼可辨。

## 常见问题

**Q：页面空白 / 游戏不初始化？**
检查浏览器控制台。若报 `Failed to fetch dynamically imported module`，
多半是某个 `.js` 的 MIME 类型不对 —— 请用 `python serve.py` 而不是直接双击
`index.html`（`file://` 协议不支持 ES Modules）。

**Q：首次加载很慢？**
请确认用的是 `serve.py` 而不是 `python -m http.server`。后者只监听 IPv4，
浏览器访问 `localhost` 时会先尝试 IPv6 并等待约 2 秒超时。
若必须用 `python -m http.server`，请改用 <http://127.0.0.1:8000/> 访问。

**Q：切到别的标签页，回来后游戏卡住了？**
不会。游戏逻辑使用 `src/core/scheduler.js` 的非节流调度器，
在后台也会继续推进；渲染由 RAF 负责，回到标签页即恢复画面。

**Q：怎么复现上一局？**
在分享弹窗里复制深链接，或手动把 `?seed=xxx` 加上其它参数。

**Q：手机能玩吗？**
可以。布局是响应式的，竖屏 / 横屏都做了适配，核心按钮支持触控。
窄屏（≤900px）下界面自动从「左右两栏」切换为「上下堆叠」：
玩家卡片变成可横向滑动的卡片条，棋盘独占整行（始终完整可见、不被压缩变形），
右侧排行栏收起，可通过菜单 → `财务指标总览` 查看财务指标。

正方形环道棋盘在窄屏下会整体缩放（保持四边等长的轮廓比例），
格子里的机构名在极窄时会自动省略号截断，不会溢出格子。
